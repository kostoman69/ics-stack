ICS Tools — Installation & Upgrade

Quick reference for bootstrapping icstools on a Windows host, initializing an environment, and installing or upgrading the ICS Backend — online or fully offline.

1Prerequisites

Confirm these before starting, whether the host is connected or offline.

  • 64-bit Windows Server, from an elevated (Run as Administrator) console.
  • HTTPS access to icsauth.net — or an approved offline-media process (see Offline installation).
  • The target environment name and installation root already decided.
  • Service-account and Api database-provider information on hand, for config init.
  • IIS, URL Rewrite, and ARR installed when the host uses an IIS reverse proxy.
  • The .NET 10 Hosting Bundle — icstools bootstrap installs it automatically when the host has internet access; otherwise install it by hand first (see Offline installation).

2First installation (online)

Run once, on a host with internet access, to install icstools itself. This does not install the Backend or initialize an environment — see the next sections.

STEP 1Download and verify the bootstrap package

# from an elevated Command Prompt, in a working folder of your choice
curl.exe -fL https://icsauth.net/data/ics/11-tooling/icstools-bootstrap-win-x64.zip -o icstools-bootstrap-win-x64.zip
curl.exe -fL https://icsauth.net/data/ics/11-tooling/bootstrap.json -o bootstrap.json
certutil.exe -hashfile icstools-bootstrap-win-x64.zip SHA256

Compare the reported SHA-256 against the sha256 value in bootstrap.json. Stop and re-download if they differ — do not run a package with a mismatched hash.

Windows Server < 2019 — curl.exe and tar.exe may not be present. Use PowerShell instead: 
Invoke-WebRequest -Uri "https://icsauth.net/data/ics/11-tooling/icstools-bootstrap-win-x64.zip" -OutFile "icstools-bootstrap-win-x64.zip"
Invoke-WebRequest -Uri "https://icsauth.net/data/ics/11-tooling/bootstrap.json" -OutFile "bootstrap.json"

STEP 2Extract and run bootstrap

tar.exe -xf icstools-bootstrap-win-x64.zip
# or unzip icstools-bootstrap-win-x64.zip through Explorer if tar.exe is unavailable
.\icstools.exe bootstrap

Installs icstools.exe to C:\opt\ics\bin, adds it to the machine PATH, and installs the .NET 10 Hosting Bundle if it isn't present yet. Add --yes to accept prerequisite installation without an extra confirmation prompt.

Already installed? Skip both steps above and just run icstools upgrade instead — see Upgrading.

Open a new elevated console after bootstrap completes, so the updated PATH is visible.

3Initialize the host environment

Bootstrap only installs the tool — it never touches ICS configuration by itself. Run this separately, on every host:

icstools config init

Prompts interactively for the environment, or run non-interactively with:

icstools config init --environment <environment>

Valid environments:

  • Development
  • Test
  • QA
  • QaS
  • QaO
  • Production

4First Backend installation

Api, App, and Cnx are always installed, upgraded, and rolled back together as one aligned release. Host-managed Backend commands are available only on a configured Production host — Development/Test/QA Backend deployment is pipeline-managed, not host-managed.

icstools backend versions
icstools backend upgrade
icstools backend status

To install an explicitly approved build instead of the latest:

icstools backend upgrade --build 854

backend upgrade shows "current → target" and asks for confirmation before doing anything, unless --yes/-y is given.

5Upgrading icstools and the Backend

TOOLINGicstools itself

icstools upgrade --check   # see what's available, change nothing
icstools upgrade           # interactive upgrade
icstools upgrade status    # durable status of the last attempt

Use icstools upgrade --yes for an unattended, already-approved upgrade. On Windows, the elevated updater records durable status under C:\ProgramData\FORTH\ICS\Tooling\Updates.

BACKENDApi / App / Cnx

In Production, prefer /tools/version in the App itself. From the command line:

icstools backend versions
icstools backend upgrade
icstools backend status
icstools backend rollback     # repoints to the nearest aligned older release
Environment boundary — backend commands derive the configured host identity and run only on Production; they never accept --environment/--env. Use the matching Azure deployment pipeline with an explicit BuildId for Test/QA. Bootstrap and config init remain available for provisioning those environments.

6Offline / air-gapped installation

For a host with no network access at all, everything above still applies — you just fetch each artifact on a connected machine first, transfer it through your approved offline-media process (USB or similar), then run the same commands with one extra flag.

PHASE AOn a machine with internet access

  1. Download and verify the icstools bootstrap package exactly as in Step 1 above (zip + bootstrap.json + SHA-256 check).
  2. Download the .NET 10 Hosting Bundle installer — the offline target cannot reach Microsoft's servers, so icstools bootstrap can't fetch it there: 
    curl.exe -fL https://aka.ms/dotnet/10.0/dotnet-hosting-win.exe -o dotnet-hosting-10.0-win.exe
  3. If the host also needs the ICS Backend, build an offline installation bundle for the approved build: 
    icstools backend pack --build 854 --out ics-backend-854.zip
    This bundles the target build together with any compatibility-bridge releases it declares, and its release notes when published.

PHASE BTransfer

Copy everything gathered in Phase A to the target host through your organization's approved offline-media process. Keep the transferred media until acceptance and rollback checks complete.

PHASE COn the offline target host (elevated console)

# .NET 10 Hosting Bundle — install manually first (double-click, or silently):
dotnet-hosting-10.0-win.exe /quiet /norestart

# Tooling — --skip-runtime asserts the prerequisite was handled separately;
# it does not waive the requirement, so install the Hosting Bundle first.
tar.exe -xf icstools-bootstrap-win-x64.zip
.\icstools.exe bootstrap --skip-runtime
icstools config init --environment Production

If the Backend is also needed:

mkdir D:\ics-backend-854
tar.exe -xf ics-backend-854.zip -C D:\ics-backend-854
icstools backend upgrade --offline-bundle D:\ics-backend-854
Tooling upgrades have no offline-bundle option. Unlike backend upgrade, plain icstools upgrade does not accept --offline-bundle. To move an offline host to a newer icstools release later, repeat Phase A/B/C above with the newer bootstrap package — icstools bootstrap detects the existing install and simply tells you to run icstools upgrade instead, so on an air-gapped host, replace the binary and appsettings.json in C:\opt\ics\bin by hand from a freshly downloaded bootstrap package, or coordinate with the platform team for an approved manual-copy procedure.

7Troubleshooting

SymptomWhat to do
Bootstrap package hash mismatchDelete the package and download it again — do not run a package that fails verification.
.NET Hosting Bundle install failsInstall the prerequisite manually, reboot if required, then rerun icstools bootstrap (or --skip-runtime once it's confirmed installed).
icstools upgrade failsInspect icstools upgrade status; fix the reported elevation, filesystem, or verification problem. Do not repair the installation junction by hand.
Host configuration step failsCorrect the reported account, ACL, service, registry, or IIS problem, then rerun the same idempotent command.
Release server unreachableCheck DNS, TLS, proxy, and firewall from this host; if it's genuinely air-gapped, use the offline procedure above instead.
